# Optional Read Aloud v0.1

## Scope and design

North star: a quiet, optional way to listen to an individual Bloom reply without taking focus from reading or composing. The existing Vue 3 / uni-app chat and FastAPI chat contract are extended; DeepSeek prompts, thinking settings and budget are unchanged.

Final assistant messages gain a speaker action beside Copy. Active playback adds pause/resume, stop and local speed selection (0.8, 1, 1.25, 1.5). Loading is distinct from playing; native `onPlay` confirms success. No background narration, autoplay on new messages, microphone permission, voice cloning, model request or paid service activation is introduced. A short press treatment and restrained state transitions follow the existing theme; no extra illustration or large player card is needed.

The first explicit click opens a compact **inline notice above the composer**, with Enable and read, Skip, and an expandable explanation. The textarea, draft and keyboard remain available; playback does not open a modal. Declining sends nothing to TTS. Accepting authorizes that selected reply; accepting through Settings enables subsequent explicit clicks without playing anything. Consent versions are provider-mode specific: changing from Mock to Tencent requires a new user consent before any transmission. Settings → Read Aloud and voice privacy retains its dedicated management sheet for revocation and cache deletion. Mock is labelled in disclosure and playback and plays an eight-second repository-generated tone, **not synthesized speech or a Tencent voice sample**.

## Backend and contract

`app/tts_provider.py` defines `TTSProvider`, offline `MockTTSProvider`, and `TencentTTSProvider` using HTTPS TextToVoice 2019-08-23 and TC3-HMAC-SHA256. Only backend `.env` holds credentials. `SecretStr` prevents settings representations exposing them. The adapter has an additional paid-enable guard before HTTP dispatch; keys alone never enable requests. It returns bounded, validated MP3 data and never logs upstream error bodies, signed headers or text.

- `GET /api/speech/config`: mode, availability, consent, maximum text and cache duration. No credentials.
- `PUT /api/speech/consent {accepted}`: explicit, versioned record in the existing `consents` table. Revocation removes all user audio including in-flight reservations. Reacceptance cannot resurrect a revoked job.
- `POST /api/conversations/{id}/speech`: `{message_id}` for stored final assistant messages. For chat retention off, `{text, proof}` must match the exact final reply signed by the server. A `speech_proof` is added only to completed, unretained chat responses. It includes user, conversation, version, completed chat request, text hash, privacy epoch and expiry, never private model context. Proofs expire after one hour and on API restart, source change, privacy change or conversation deletion; there is no fallback to trusting arbitrary client text.
- `GET /api/speech/audio/{id}/{index}`: authenticated MP3; rechecks owner, current consent, source existence/content or unretained proof. Relative part paths are under `/api`. No public/signed bearer URL, object bucket, static audio directory or cross-user sharing.

The reply is capped at 1,200 characters by default, then split at sentence boundaries into <=120 codepoints / <=450 UTF-8 bytes per TextToVoice call. This stays below its published 150-Chinese/500-English limit and handles emoji safely. Each segment is a separate MP3 played sequentially; MP3 files are not naively concatenated. A single user gesture authorizes this bounded sequence. All segments are synthesized before playback; changing speed never synthesizes again.

`speech_audio` stores only private MP3 segments, source IDs/proof/hash and expiry, not a duplicate plaintext transcript. Cache identity includes owner, conversation, source, exact text hash, provider, voice and codec version. Successful audio expires after one hour (configurable); authenticated accesses also purge expired rows. An application lifecycle sweeper removes expired data every 60 seconds. Revocation, source deletion, retention disable and account deletion remove/revoke audio. Never use retention off as permission to store plaintext; the speech consent discloses the separate temporary audio cache.

`speech_usage` is independent of AI budgets. Atomic daily reservations enforce per-user 3,000 characters / 20 synthesis jobs and global 10,000 characters / 100 jobs by default (Shanghai day). All segments count toward the full-text reservation. Cache hits consume no reservation; failures conservatively retain theirs. Counters contain no transcript and expire after 32 days. Across workers, the unique pending cache key and transactional limits reject duplicates. If a submitted synthesis times out or fails, its key stays blocked for up to 24 hours, because the upstream billing result may be unknown. No automatic retry or refund assumption is made. Repeated accesses never trigger synthesis, and cache expiry only permits regeneration after another explicit click.

SQLite creates the two additive tables on normal development startup. PostgreSQL deployment requires `20261023030000_read_aloud.sql`; it enables RLS and revokes direct public/client roles. Development QA uses a disposable database only. Missing tables return HTTP 503 with `speech_setup_required`; database exceptions never expose SQL or connection details to the client. The expiry worker logs only a safe category and survives temporary storage failures.

## Configuration

Repository defaults: `AGENCY_TTS_MODE=mock`, `AGENCY_TTS_PAID_ENABLED=false`, voice `101001`, region `ap-guangzhou`. Store `AGENCY_TTS_SECRET_ID` and `AGENCY_TTS_SECRET_KEY` **only** in the ignored `apps/api/.env`. See `.env.example` for limits. Enabling real service requires explicit spending authorization and Tencent TTS service/voice access. There is no startup probe or automatic free-trial call. Keep DeepSeek's CNY 100/month and overall CNY 500/month unchanged.

Operational follow-up, 2026-10-23: the user explicitly authorized real Tencent synthesis. The local ignored environment now selects Tencent with the paid guard enabled. One deliberately bounded, ten-character connectivity test returned a valid MP3 (10,080 bytes); no user chat text was used. The reported generic error was traced to the configured PostgreSQL database missing both speech tables. The reviewed, additive Read Aloud migration was applied as the live repair; existing account/transcript rows were not altered. All development regression tests continue to use isolated databases and MockTransport.

For deployment, configure an HTTPS API domain in the Mini Program request **and downloadFile** legal-domain lists. The phone must reach that domain; localhost works only for local tools. Use a supported WeChat base library (playbackRate requires 2.11.0+). Playback obeys the device's mute switch. Only an authenticated `uni.downloadFile` receives audio; its temporary path feeds `uni.createInnerAudioContext()`. Stop/switch/page hide/logout invalidates pending callbacks, aborts download tasks, destroys contexts, and unlinks temporary files; a download arriving late is deleted instead of played. No local audio is saved persistently.
